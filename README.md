# Оракул школы (Edu_Bot) — готовый к запуску проект

Бот школьного расписания МБОУ СОШ №19 имени Романа Катасонова. Работает
**одновременно в VK и в MAX** — один Python-процесс, общий кэш расписания,
меню и замен. Отвечает обычным текстом на расписание класса/учителя, меню
питания и изменения в расписании; для завучей — пошаговый подбор замены
отсутствующему педагогу с автогенерацией xlsx-файла.

- **MAX:** бот `ideya_fiks_7_bot` → https://max.ru/ideya_fiks_7_bot
- **VK (сообщество):** https://vk.ru/club242725074

В этом архиве уже лежат реальное расписание, меню и готовые кэши — проект
нужно просто загрузить на сервер/хостинг и запустить одной командой (см.
раздел 2). Токены уже вписаны в `school_bot.py`, их можно переопределить
переменными окружения `VK_TOKEN` / `MAX_TOKEN`, если понадобится сменить их
без правки кода (например, при развёртывании через Docker).

## 1. Что внутри

```
school_bot.py          — весь бот (расписание/меню/замены, VK- и MAX-клиенты)
requirements.txt        — зависимости Python с точными версиями
Dockerfile
docker-compose.yml
schedule.xlsx            — расписание (2026–2027, корпус 1)
меню 1-4.xlsx             — меню питания, 1–4 классы
меню 5-11.xlsx            — меню питания, 5–11 классы
schedule_cache.pkl        — уже собранный кэш расписания (пересоберётся сам,
                            если schedule.xlsx станет новее этого файла)
menu_1_4_cache.pkl, menu_5_11_cache.pkl — уже собранные кэши меню
log_error.txt, log_statistic.txt        — логи (см. раздел 4, создаются пустыми)
russian_trusted_ca.pem    — сертификат для доступа к API MAX (см. раздел 5)
```

## 2. Быстрый запуск (без Docker)

```bash
cd <папка-с-проектом>
python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
python3 school_bot.py
```

Если в консоли появилась строка `... - VK бот запущен ✅` и `... - MAX бот
запущен ✅ (long polling)` без ошибок — бот поднялся и отвечает в обоих
мессенджерах.

Бот не даст запустить второй процесс параллельно (файл-блокировка
`school_bot.lock`) — это защита от задвоенных ответов в VK, если забыть про
старый запущенный процесс.

## 3. Запуск в Docker (альтернатива)

```bash
docker build -t edu-bot .
docker run -d \
  --name edu_bot \
  --restart unless-stopped \
  -v "$(pwd):/app" \
  edu-bot
docker logs -f edu_bot
```

Либо через docker-compose (тот же результат, удобнее для постоянной
работы):

```bash
docker compose up -d --build
docker compose logs -f
docker compose restart     # например, после замены schedule.xlsx
docker compose down
```

Токены уже вписаны в `school_bot.py` — отдельно ничего задавать не нужно.
Если понадобится переопределить их без правки кода, раскомментируйте блок
`environment:` в `docker-compose.yml` и создайте рядом `.env`:

```env
VK_TOKEN=...
MAX_TOKEN=...
```

## 4. Приватность и логи

Бот **не собирает и не хранит личные данные пользователей**: ни имена, ни
ID профилей, ни историю переписки. На диск пишутся только два технических
лог-файла:

- **`log_statistic.txt`** — обезличенная статистика обращений: только
  количество запросов по классам/учителям. Кто и сколько раз писал боту —
  не фиксируется.
- **`log_error.txt`** — только нераспознанные/ошибочные запросы и сетевые
  сбои VK/MAX API. От кого пришёл такой запрос — не фиксируется.

## 5. Обновление данных

- **Расписание:** замените `schedule.xlsx` на новый файл и перезапустите
  бота — если файл новее сохранённого `schedule_cache.pkl`, кэш
  пересоберётся автоматически.
- **Меню:** аналогично для `меню 1-4.xlsx` / `меню 5-11.xlsx`.
- **Замены:** через диалог «замены» в самом боте, либо пришлите ему файлом
  xlsx (имя начинается с «Замены») или docx («Изменения в расписании
  на…») — см. текст команды «начало» в самом боте, там полная инструкция.

## 6. Известные особенности

- **MAX и сертификаты.** `platform-api2.max.ru` использует сертификат
  Национального удостоверяющего центра Минцифры, которого нет в обычном
  системном хранилище. Бот сам скачивает и кэширует его
  (`russian_trusted_ca.pem`, уже лежит в этом архиве) при первом запуске;
  если у сервера нет доступа в интернет до `gu-st.ru` — файл уже на месте,
  ничего дополнительно делать не нужно.
- **Один процесс — один ответ.** Если запустить бота дважды (например,
  забыв про старый процесс), VK Long Poll разошлёт сообщение в оба
  процесса, и оба ответят — отсюда защита файл-локом (`school_bot.lock`),
  см. раздел 2.
